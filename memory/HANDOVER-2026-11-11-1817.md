# Session Handover — 2026-11-11 18:17

## Session Summary
Built ClickerFex from an empty repo: a web app (Vercel) that turns a phone into a presentation clicker with touchpad, prev/next, gyroscope laser and voice dictation, paired to a computer by QR. An optional desktop agent (Windows/macOS executables built by GitHub Actions) injects real OS mouse/keyboard input. Owner validated it in real use on Android and is sharing it with a Mac + iPhone user.

## What Was Done
- Vite + TypeScript static site: `/` = receiver (laptop), `/remote` = phone controller. Deployed at https://clickerfex.vercel.app (Vercel project `clickerfex`, team `fexs-projects-fa581e8c`, auto-deploys on push to this branch, which is the repo default branch).
- Pairing: PeerJS WebRTC data channel, 5-char code (no 0/O/1/I/L), QR to `/remote#CODE`; code persisted in localStorage so reloads keep it; heartbeat ping/pong every 2 s.
- Modes: **PDF** (pdf.js renders slides in the page, laser + virtual cursor drawn as overlays, zero install) and **System** (receiver forwards to agent on `ws://localhost:8765`).
- Phone UI: touchpad (acceleration, tap = click, 2-finger tap = right click, 2-finger drag = scroll), prev/next (pointerdown for latency), hold-to-laser (toggle option), wake lock, settings sheet.
- Laser rewritten to absolute pointing: direction of the phone's top edge (device +Y) in world frame → yaw/pitch → screen position by angle; centred on press; roll-independent; One Euro filter. `RelativeOrientationSensor` quaternion first, `deviceorientation` Euler fallback. Setting = horizontal FOV in degrees (default 30°).
- Agent (`agent/clickerfex_agent.py`, pynput + websockets): move/click/scroll/keys/text; red laser dot (Windows: `SetSystemCursor` swap, restored via `SPI_SETCURSORS`; macOS: click-through topmost NSWindow overlay + hidden cursor via private `SetsCursorInBackground`); `--selftest`, `--no-dot`, `--origin`, `--screen`.
- CI `.github/workflows/agent.yml`: PyInstaller onefile for windows-latest and macos-latest (arm64), smoke test + selftest on real runners, uploads to release tag `agent-latest`.
- Dictation sheet (system mode only): Web Speech API, each final phrase typed on PC; textarea + Enviar; Backspace/Tab/Enter keys. Fixed joining space before punctuation.
- iOS fix: Motion & Orientation permission requested on first laser tap (touchend/click), not pointerdown.

## Key Decisions Made
- **Decision**: Two modes (PDF in-browser + optional native agent) instead of web-only.
  - **Context**: User wanted no installs on university PCs but also control of PowerPoint/whole OS.
  - **Rationale**: Browsers cannot inject OS input. PDF mode covers zero-install; agent covers full control. Agent connects via the receiver tab (localhost WS), avoiding WebRTC in Python.
- **Decision**: PeerJS public broker for signaling, P2P data.
  - **Context**: Vercel serverless has no WebSockets; no backend wanted.
  - **Rationale**: Zero infra, LAN latency. Self-host path documented via `VITE_PEER_*` env vars. Risk: broker outage blocks pairing.
- **Decision**: Absolute orientation laser, not integrated `rotationRate`.
  - **Context**: User reported first version felt like "tilting", counterintuitive; Android `rotationRate` axes unreliable.
  - **Rationale**: Pointing = same direction always maps to same spot; roll ignored. Relative sensor (no magnetometer) avoids projector/metal interference; yaw drift negligible because centre recalibrates each press.
- **Decision**: Laser sends absolute `lpos` (0..1), not deltas.
  - **Rationale**: Lost/late messages don't accumulate error; agent maps directly to screen.
- **Decision**: Agent accepts only exact origin `https://clickerfex.vercel.app` + localhost.
  - **Rationale**: Any site could otherwise drive the mouse; `clickerfex-*.vercel.app` wildcard rejected because anyone can register such a project name.
- **Decision**: Agent bridge only on explicit "Conectar agente" (remembered in localStorage).
  - **Rationale**: Probing localhost triggers Chrome's local-network permission prompt for every visitor.
- **Decision**: Windows red dot via system cursor swap; macOS via overlay window.
  - **Rationale**: macOS forbids changing another app's cursor; Windows cursor swap shows over fullscreen PowerPoint with no focus issues. Failures degrade to plain cursor; restore on release/disconnect/exit/startup.
- **Decision**: macOS: custom AppKit loop (`nextEventMatchingMask`) on main thread, WS server on worker thread.
  - **Rationale**: Deterministic, honours Ctrl+C and stop event; avoids NSApplicationMain quirks in unbundled PyInstaller binary.
- **Decision**: Binaries distributed via GitHub release `agent-latest`, links hardcoded in `index.html`.
  - **Rationale**: Fast; but repo is private → only logged-in owner can download (see Open Questions).

## Pitfalls & Gotchas
- PeerJS broker (`0.peerjs.com`) and `*.vercel.app` are blocked by this container's proxy: e2e tests use local `npx peer@1.0.2 --port 9000 --host 127.0.0.1` (needs `--host`, IPv6 fails) and `VITE_PEER_HOST=127.0.0.1`.
- Chromium now exposes `DeviceMotionEvent/DeviceOrientationEvent.requestPermission`; returns `prompt` without activation. Only treat explicit `denied` as fatal.
- `RelativeOrientationSensor` in tests needs `context.grantPermissions(['accelerometer','gyroscope'])`; CDP `Emulation.setSensorOverrideReadings` drives quaternions.
- iOS: permission prompt only from touchend/click — pointerdown silently rejected (fixed).
- Chromium exposes unprefixed `SpeechRecognition`; mocks must override both names.
- PyInstaller: `collect_submodules(pynput)` skips the backend if it can't import at build time (no DISPLAY on Linux) → pass `--hidden-import pynput.{keyboard,mouse}._win32/_darwin`.
- Windows CI: running exe locks it → Copy-Item, kill smoke-test PID.
- Old agent left running holds port 8765 → new one fails ("¿Ya hay otro agente abierto?"); user hit this. Startup line `láser: …` identifies new versions.
- Vercel project initially had SSO protection `all_except_custom_domains`; changed to `preview` so production is public.
- No tkinter in container Python; desktop text-field test uses headed Chromium on Xvfb.
